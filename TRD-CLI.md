## 1. Architecture at a glance

```
            ┌──────────── shared/ (canonical, repo root) ────────────┐
            │ extraction-prompt.md · card-spec.md · fixtures/         │
            └───────────────┬───────────────────────────┬─────────────┘
                 sync + hash check                 sync + hash check
                            │                           │
        ┌───────────────────▼────────┐      ┌───────────▼───────────┐
        │ cli/  (Node, zero deps)    │      │ Swift app (unchanged  │
        │ npm: context-shifter       │      │ behaviour)            │
        └───────────────────┬────────┘      └───────────────────────┘
                            │
   stdin/file → normalize → [redact] → plan → backend(s) → postprocess → validate → emit
                                         │
                                  chunk + merge if over budget
```

Principles: **zero runtime dependencies**, **stdout is the card only**, **local-first with an enforceable offline mode**, **the card format is a versioned contract shared with the Mac app**.

## 4. CLI surface

### 4.1 Commands

```
context-shifter extract [file|-] [options]     # default command if input is piped
context-shifter doctor
context-shifter models                          # P1: list local Ollama models
context-shifter config get|set|list|path        # P1
context-shifter --version | --help
```

**Compatibility shim (finding F1):** `--extract` is accepted as a hidden alias for the `extract` command, so the landing page's `pbpaste | context-transfer --extract` continues to work once the binary is renamed. `--capture` is intentionally not implemented; it prints `--capture is macOS-only; use the Context Transfer app` and exits 2.

### 4.2 `extract` options

| Flag | Default | Notes |
|---|---|---|
| `--backend ollama\|anthropic\|nim` | `ollama` | |
| `--model <id>` | per backend | |
| `--level full\|balanced\|minimal` | `balanced` | Same semantics as the app (R3). |
| `--copy` | off | R15 |
| `--out <file>` | stdout | R16 |
| `--json` | off | P1, R17 |
| `--offline` | off | R13: refuse non-loopback backends. |
| `--redact` | off | P1, R18 |
| `--from chatgpt-export\|claude-export` | plain text | P1, R19 |
| `--ctx <tokens>` | 8192 (Ollama) | P1: raise if the user has VRAM; scales the chunk budget. |
| `--max-input <bytes>` | 10 MB | Guard against accidental huge pipes. |
| `--quiet` | off | Suppress stats/progress on stderr. |
| `--no-color` | auto | Also honours `NO_COLOR`. |

**API keys are never flags** (R12). Env vars only in v0.1: `ANTHROPIC_API_KEY`, `NVIDIA_API_KEY`. (Config-file key storage is deferred: Windows can't enforce `0600`, so it isn't worth the false sense of security.)

### 4.3 Configuration precedence

`flags` > `environment` > `user config file` > `built-in defaults`.

Env: `OLLAMA_HOST` (default `http://127.0.0.1:11434`), `NIM_BASE_URL` (default `https://integrate.api.nvidia.com/v1`; lets people point at a self-hosted NIM), `CONTEXT_SHIFTER_BACKEND`, `CONTEXT_SHIFTER_MODEL`, `CONTEXT_SHIFTER_LEVEL`, `NO_COLOR`.

Config file (P1): `$XDG_CONFIG_HOME/context-shifter/config.json` (fallback `~/.config/...`) on Linux/macOS; `%APPDATA%\context-shifter\config.json` on Windows. Holds non-secret defaults only.

### 4.4 Output contract

- **stdout:** the card (or JSON with `--json`). Nothing else, ever.
- **stderr:** progress, stats, warnings, errors.
- If stdout is piped, no ANSI codes are emitted anywhere on stdout.

### 4.5 Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | Unexpected error |
| 2 | Usage error (bad flag, unsupported combo such as `--offline` with a cloud backend, empty input) |
| 3 | Backend unreachable (Ollama down, DNS/timeout) |
| 4 | Auth failure (missing/invalid key, 401/403) |
| 5 | Card failed validation after retry (card is still printed; a warning goes to stderr) |

## 5. Shared assets and drift prevention (finding F4, F5)

### 5.1 Canonical files

`shared/extraction-prompt.md` is the single source of truth for the prompt. It uses front matter plus named blocks split by HTML-comment markers, so both Swift and Node can parse it with a trivial split and it stays reviewable in PRs:

```markdown
---
spec_version: 1
---
<!-- @block system -->
...role, output format, verbatim-links rule, no-preamble rule...
<!-- @block level:full -->
...
<!-- @block level:balanced -->
...
<!-- @block level:minimal -->
...
<!-- @block merge -->
...instructions for combining partial cards (see §8)...
<!-- @block retry -->
...appended on validation retry; contains {{REASONS}}...
```

`shared/card-spec.md` documents the card format normatively: section names and order, heading level, the `Captured on` line, verbatim-link rule, per-level limits, and `CARD_SPEC_VERSION`. The validators in both languages implement this document.

### 5.2 Why a sync step exists

A Swift package can only bundle resources inside its target directory, and `npm publish` only ships files under `cli/`. Neither can read `../shared` at runtime. So each consumer holds a **generated copy**:

- CLI: `cli/prompts/extraction-prompt.md`, produced by `scripts/sync-prompt.mjs` on `prepack` (and by a `postinstall`-free dev script). Git-ignored.
- Swift: a committed copy under the target's resources, produced by a small `Scripts/sync-shared.sh`.

`sync-prompt.mjs` copies the file, writes `prompts/manifest.json` with `{ spec_version, sha256 }`, and fails if `shared/` is missing.

### 5.3 Drift check (CI, required)

A job runs `scripts/check-shared` and fails the build if **any** consumer copy's SHA-256 differs from `shared/extraction-prompt.md`, or if `spec_version` differs anywhere. This is the enforcement behind "same prompt, same card".

### 5.4 The one touch on the Mac app

If the app currently embeds the prompt as a Swift string **(verify)**, the only required app change is to load it from the synced resource instead. Behaviour must be unchanged, and the existing Swift tests plus the shared fixtures are the proof. If you want zero app changes for now, start with `shared/extraction-prompt.md` as a copy of the app's current prompt and add the Swift-side drift check later; the CLI is unaffected either way.

### 5.5 Shared fixtures

`shared/fixtures/cards-valid/*.md` and `cards-invalid/*.md` (each invalid file paired with an expected reason code, e.g. `MISSING_SECTION`, `FABRICATED_URL`, `LEVEL_LIMIT`). Both the Swift tests and the Node tests iterate the same directories and assert identical verdicts. This is the parity metric in the PRD.

## 6. Extraction pipeline

```
1. Read input          io/input.ts       file | stdin | TTY paste mode
2. Decode + normalize  io/encoding.ts    BOM, UTF-16, CRLF→LF, strip ANSI, trim
3. Parse (optional)    parsers/*         export JSON → transcript text
4. Redact (optional)   core/redact.ts    before anything leaves the process
5. Plan                core/pipeline.ts  estimate tokens vs backend budget → single | chunked
6. Run                 backends/*        single call, or map → reduce (§8)
7. Postprocess         core/card.ts      strip fences/chatter, drop model "Captured on", inject ours
8. Validate            core/validate.ts  §9; on failure retry once with reasons
9. Stats               core/tokens.ts    prefer real usage from the API, else chars/4
10. Emit               stdout / --out / --copy / --json
```

Sampling: `temperature: 0.1`. Extraction should be as deterministic as the backend allows.

### 6.1 Backend interface

```ts
export interface CompletionRequest {
  system: string;
  user: string;
  maxOutputTokens: number;
  temperature: number;
}
export interface CompletionResult {
  text: string;
  usage?: { inputTokens: number; outputTokens: number };
}
export interface Backend {
  readonly id: 'ollama' | 'anthropic' | 'nim';
  readonly isLocal: boolean;               // loopback host only; drives --offline
  readonly inputBudgetTokens: number;      // usable input tokens per call, after reserves
  complete(req: CompletionRequest, signal: AbortSignal): Promise<CompletionResult>;
  preflight(): Promise<{ ok: boolean; detail: string }>;   // used by `doctor`
}
```

`isLocal` is computed from the **resolved host** (loopback check on `127.0.0.0/8`, `::1`, `localhost`), not from the backend id, so a remote `OLLAMA_HOST` correctly counts as non-local.

## 7. Backends

### 7.1 Ollama (default)

- `POST {OLLAMA_HOST}/api/chat` with `{ model, messages: [{role:'system',...},{role:'user',...}], stream: false, options: { num_ctx: 8192, temperature: 0.1 } }`. Response text is `message.content`; real counts are `prompt_eval_count` and `eval_count`.
- **`num_ctx` is always set explicitly.** Ollama's default window has historically been smaller than people assume and silently truncates the prompt, which produces cards that ignore the beginning of the conversation. The app already sets 8K for this reason; the CLI mirrors it (`--ctx` to raise it).
- `GET {OLLAMA_HOST}/api/tags` lists installed models (used by `models` and `doctor`).
- Timeout: 120 s per call (cold model load can be slow), no automatic retry on timeout beyond the single validation retry.
- `ECONNREFUSED` → exit 3 with `Ollama isn't reachable at <host>. Start it with: ollama serve`. Model not found → exit 3 with `ollama pull <model>`.
- Default model: mirror the app's default **(verify: README example says `llama3.2:3b`, the landing page says `llama3.1:8b`; pick one and put it in the shared spec, F3)**. `doctor` warns if the chosen model is very small, since small models fail validation more often.

### 7.2 Anthropic

- `POST https://api.anthropic.com/v1/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`. Body `{ model, max_tokens, temperature, system, messages: [{role:'user', content}] }`. Text is the concatenation of `content[].text` blocks; usage from `usage.input_tokens` / `usage.output_tokens`.
- Default model mirrors the app (`claude-sonnet-4-6` per the README). Model IDs are just strings, so `--model` covers newer ones; decide whether app and CLI defaults move together (PRD D6).
- 401/403 → exit 4. 429/5xx → up to 2 retries with exponential backoff + jitter, honouring `retry-after`. This transport retry is separate from the validation retry.
- Input budget: 100k tokens by default (conservative; well under the model's real window).

### 7.3 NVIDIA NIM

- OpenAI-compatible: `POST {NIM_BASE_URL}/chat/completions`, `Authorization: Bearer $NVIDIA_API_KEY`, body `{ model, messages, temperature, max_tokens }`. Text is `choices[0].message.content`; usage from `usage.prompt_tokens` / `usage.completion_tokens`.
- Default base URL `https://integrate.api.nvidia.com/v1`. **Model IDs and free-tier limits change; verify at build time** and don't hard-code more than one default.
- Input budget: 24k tokens by default (varies per model; override with `--ctx`).
- Same error/retry policy as Anthropic.

### 7.4 `--offline`

Before any network I/O, resolve the backend's host. If not loopback → exit 2: `--offline set but <backend> would send data to <host>`. A test opens a listening socket on a non-loopback-looking mock and asserts zero connections. This makes the site's "0 network calls on the extraction path" claim a tested property of the CLI. The CLI performs **no update checks and no telemetry**, ever.

## 8. Chunking and merge (finding F8, R7)

### 8.1 Budget

```
inputBudget = window − promptTokens − outputReserve − safetyMargin
```

For Ollama at 8192: `promptTokens` measured from the loaded prompt, `outputReserve` ≈ 1500, `safetyMargin` ≈ 300, then multiplied by **0.8**, because `chars/4` underestimates tokens for code, URLs and non-Latin scripts. Cloud backends use the fixed budgets in §7.

### 8.2 Algorithm

1. If `estimate(input) ≤ inputBudget` → single call.
2. Split into **turns**: prefer speaker labels (`/^(user|you|me|human|assistant|chatgpt|claude|gemini|ai)\s*[:>]/im`), else blank-line paragraphs, else lines, else sentence boundary as a last resort. Never split inside a fenced code block if avoidable.
3. Greedy-pack turns into chunks ≤ `inputBudget`, with an overlap of the last 1–2 turns (≤ 10% of budget) so context isn't cut mid-thought.
4. **Map:** extract each chunk at level `full` (keep detail for the merge), labelled "Part i of n, chronological". Sequential for local backends; concurrency of 3 for cloud.
5. **Reduce:** send the partial cards to the `merge` prompt block at the **requested** level. If the concatenated partials still exceed budget, reduce recursively in groups.
6. Merge rules (in the prompt): chronological order; **later state overrides earlier**; a decision reversed later is dropped or noted as superseded; union of links, de-duplicated, verbatim; an open question answered later is removed.
7. Validation runs on the **final** card only. Link fidelity (§9) checks against the **entire original input**, not a chunk.

Progress on stderr: `chunk 2/5 …` when stderr is a TTY.

Known weak spot: merge quality on very long, meandering conversations. Golden fixtures with known decisions exist to catch regressions (§13).

## 9. Validation (R4, R5)

Post-processing first, then rules. Codes are shared with the Swift fixtures.

**Post-processing**
- Strip a wrapping code fence and any preamble/postamble outside the card ("Here's your context card…").
- Remove any model-produced `Captured on` and prepend ours: `Captured on: 2026-09-20` (ISO 8601 date; full timestamp appears only in `--json`). **(verify what the app emits, F7)**
- Normalise heading levels to the spec.

**Rules**

| Code | Rule |
|---|---|
| `MISSING_SECTION` | All six sections present, in spec order: Goal, Key Decisions, Constraints & Preferences, Current State, Resources & Links, Open Questions. **(verify heading level and names against the app)** |
| `EMPTY_SECTION` | No empty section; "None" is allowed for Open Questions and Resources & Links. |
| `FABRICATED_URL` | Every URL/identifier in Resources & Links appears verbatim in the (redacted) input. This is the hallucination guard for the "copy exactly" rule. |
| `LEVEL_LIMIT` | `minimal`: at most 2 short bullets per section (Resources & Links exempt, per the README). |
| `NO_COMPRESSION` | Warning, not failure: card is larger than input. Skipped for very short inputs. |

**Retry:** on failure, call again once with the `retry` block appended (`{{REASONS}}` = the rule codes plus offending items) at `temperature: 0`. If it still fails → print the card, warn on stderr, exit 5. Consistent with the app's "flag, don't silently pass".

Backport note: `FABRICATED_URL` is a small Swift addition with clear value; tracked as PRD D5.

## 10. Input handling (R1, R8)

- **Sources:** file path, `-`, or piped stdin. If stdin is a TTY and no file is given, print `Paste the conversation, then press Ctrl-D (Windows: Ctrl-Z, then Enter):` on stderr and read until EOF. Empty input → exit 2.
- **Read as bytes**, then decode:
  - `EF BB BF` → UTF-8 with BOM (strip it).
  - `FF FE` → UTF-16LE; `FE FF` → UTF-16BE (swap then decode). Windows PowerShell 5.1 pipes commonly produce UTF-16LE with BOM.
  - No BOM but many `0x00` bytes at odd offsets → treat as UTF-16LE.
  - Otherwise UTF-8 (`TextDecoder` with `fatal: false`).
- Normalize `\r\n` → `\n`; strip ANSI escape sequences (copied from terminals); trim.
- Size guard: exceed `--max-input` → exit 2 with a clear message.
- **Export parsers (P1):** `chatgpt-export` reads `conversations.json` (walk the message tree from `current_node` back to root, order by parent chain, emit `Role: text`); `claude-export` similarly. Both validate the JSON shape defensively since export formats change **(verify current formats when implementing)**. Output is plain transcript text fed into the normal pipeline.

## 11. Clipboard (R15)

No dependencies; shell out to the OS tool via `child_process.spawn` with the text on stdin:

| Platform | Command |
|---|---|
| macOS | `pbcopy` |
| Windows | `powershell.exe -NoProfile -Command "[Console]::InputEncoding=[Text.Encoding]::UTF8; Set-Clipboard -Value ([Console]::In.ReadToEnd())"` (avoids `clip.exe`'s legacy-encoding mangling of non-ASCII text) **(verify on Windows CI)** |
| Linux (Wayland, `WAYLAND_DISPLAY` set) | `wl-copy` |
| Linux (X11) | `xclip -selection clipboard`, else `xsel --clipboard --input` |
| WSL | `clip.exe` fallback |

If no tool is found or it exits non-zero: warn on stderr with an install hint, **still print the card to stdout**, and keep exit code 0 (the extraction succeeded). `doctor` reports clipboard tool availability.

## 12. Security and privacy

| Concern | Control |
|---|---|
| Keys in shell history / `ps` | Keys are env-only; no `--api-key` flag exists. |
| Accidental cloud egress | Local default; `--offline` hard-blocks; one-line stderr notice naming the destination host whenever a cloud backend is used. |
| Secrets inside transcripts | `--redact` (P1) replaces matches with `[REDACTED:type]` before any send: Anthropic (`sk-ant-…`), generic `sk-…`, NVIDIA (`nvapi-…`), AWS access key IDs, GitHub tokens (`ghp_`/`github_pat_`), Slack tokens, JWTs, PEM private key blocks, `Bearer …` headers. On cloud backends without `--redact`, the CLI **warns** if any pattern matches. Link fidelity is checked against the redacted text so redaction can't cause false failures. |
| Logging | The CLI never logs transcript content. No debug file. `--verbose` (if added) prints metadata only. |
| Supply chain | Zero runtime deps; `npm publish --provenance` from GitHub Actions; 2FA on the npm account; lockfile committed for dev deps; Dependabot on dev deps and Actions. |
| Temp files | None written. Everything is in memory. |
| Trust boundary | The transcript is untrusted data. The prompt frames it as content to summarise, not instructions; validation catches structural deviation but cannot fully prevent a hostile transcript from steering the *content* of the card. Documented in `SECURITY.md`. |

## 14. CI/CD and release

**`cli-ci.yml`** (triggers on `cli/**` and `shared/**` changes): matrix `os: [ubuntu-latest, macos-latest, windows-latest]` × `node: [20, 22, 24]` → `npm ci` → `npm test` → `npm pack --dry-run`; plus the shared-drift check (§5.3).

**`cli-release.yml`** (trigger: tag `cli-v*`):
1. Assert the tag equals `cli/package.json` version.
2. Run tests.
3. `npm publish` from `cli/` with provenance. Needs `permissions: { id-token: write, contents: read }`. Prefer npm trusted publishing (OIDC) over a long-lived token if available for your account; otherwise use a granular automation token stored as a repository secret **(verify current npm setup options)**.
4. Create a GitHub Release from the changelog section.

The existing app tag `v0.1.0` is untouched. The `cli-v*` glob does not match a `v*` pattern (it starts with `c`), so the app's existing workflow won't fire on CLI tags; confirm the trigger in `ci.yml`.

### Versioning (PRD D3)

- App and CLI version **independently**: app `vX.Y.Z`, CLI `cli-vX.Y.Z`.
- **`CARD_SPEC_VERSION`** (integer, in `shared/card-spec.md` and the prompt front matter) is the compatibility contract. Bump only for breaking card-format changes; a bump requires updating both implementations in one PR (the drift check enforces this).
- `--json` output includes `spec_version`; `--version` prints `context-shifter 0.1.0 (card spec 1)`.
- Prompt-only improvements that keep the format valid are minor bumps of both products at their own pace; the drift check ensures they land in both.

## 15. Error handling and UX rules

- Every error is a `CliError { code, message, hint }`; `main()` maps to exit codes in §4.5 and prints `error: <message>` plus an optional `hint:` line. Stack traces only with `CONTEXT_SHIFTER_DEBUG=1`.
- Errors are actionable: name the fix (`ollama serve`, `ollama pull llama3.1:8b`, `export ANTHROPIC_API_KEY=…`).
- SIGINT during a request aborts the fetch via `AbortController` and exits 130 with no partial stdout.
- Broken pipe (`EPIPE` on stdout) exits quietly.
